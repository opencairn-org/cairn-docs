# Configuration

All configuration is via environment variables prefixed with **`CAIRN_`**.
Each subsystem has its own group (`CAIRN_<GROUP>_<KEY>`), read once at
startup. This page lists every variable the server reads, with its default in
the second column. A dash means the variable has no default and stays unset
unless you provide it.

Only the `CAIRN_`-prefixed name is read. Up to 0.2.x a missing `CAIRN_*`
variable fell back to the bare name, so host variables such as `URL`,
`USERNAME`, `PASSWORD` or `SESSION_SECRET` could fill Cairn settings; since
0.3.0 they are ignored. Rename any unprefixed variables you relied on before
upgrading.

Three variables are **required**: `CAIRN_DATABASE_URL`,
`CAIRN_AUTH_SESSION_SECRET` and `CAIRN_AUTH_MASTER_ENCRYPTION_KEY`. The server
refuses to start when one is missing **or set to an empty value**. An optional
variable set to an empty value means empty, not its default: `CAIRN_NATS_URL=`
keeps NATS disabled.

`cairn config help` prints every variable the config struct reads, with its
type, default and whether it is required:

```bash
docker run --rm ghcr.io/opencairn-org/cairn-core:v0.4.0 config help
```

The OIDC variables (keyed by provider id) and `CAIRN_HTTP_RATE_LIMIT_PER_MIN`
are read separately and do not appear in that list.

:::tip
`dev.env.example` in `cairn-core` is a working local set for the Compose dev
stack. Copy it to `dev.env`; `make dev-server` sources it.
:::

## Database

| Variable | Default | Notes |
| --- | --- | --- |
| `CAIRN_DATABASE_URL` | — | **required** — `postgres://user:pass@host:5432/cairn` |
| `CAIRN_DATABASE_AUTO_MIGRATE` | `false` | run the goose migrations on boot |
| `CAIRN_DATABASE_MAX_CONNS` / `..._MIN_CONNS` | `10` / `2` | connection pool bounds |

| `CAIRN_DATABASE_LOCK_TIMEOUT` | `5s` | how long a statement waits for a lock |
| `CAIRN_DATABASE_IDLE_IN_TX_TIMEOUT` | `60s` | ends sessions idle inside a transaction |
| `CAIRN_DATABASE_APPLICATION_NAME` | `cairn` | shown in `pg_stat_activity` |

## Sign-in with an identity provider (OIDC)

Besides passwords and passkeys, users can sign in through any OpenID Connect
provider. List the provider ids, then configure each one under its own prefix.

| Variable | Default | Notes |
| --- | --- | --- |
| `CAIRN_OIDC_PROVIDERS` | — | comma-separated ids, e.g. `pocketid,google` — each id becomes a login button |
| `CAIRN_OIDC_<ID>_ISSUER_URL` | — | **required per provider** — the OIDC issuer |
| `CAIRN_OIDC_<ID>_CLIENT_ID` / `..._CLIENT_SECRET` | — | **required per provider** — confidential client |
| `CAIRN_OIDC_<ID>_NAME` | the id | label of the login button |
| `CAIRN_OIDC_<ID>_SCOPES` | `openid,email,profile` | |
| `CAIRN_OIDC_<ID>_AUDIENCE` | the client id | expected `aud` claim |
| `CAIRN_OIDC_<ID>_SKIP_AUDIENCE_CHECK` | `false` | |
| `CAIRN_OIDC_<ID>_USE_PKCE` | `true` | |
| `CAIRN_OIDC_<ID>_AUTO_PROVISION` | `true` | create an account on first sign-in |
| `CAIRN_OIDC_<ID>_AUTO_PROVISION_ROLE` | `user` | `user` or `admin` for auto-provisioned accounts |

`<ID>` is the upper-cased provider id: `CAIRN_OIDC_PROVIDERS=google` reads
`CAIRN_OIDC_GOOGLE_ISSUER_URL`.

## Maps

The interactive map in the web UI uses OpenFreeMap's key-less Liberty vector
style by default. The server renders a static snapshot of every activity
(`/api/activities/{id}/map.png`) for feeds and share links from raster tiles.

| Variable | Default | Notes |
| --- | --- | --- |
| `CAIRN_MAP_TILE_URL` | `https://tile.openstreetmap.org/{z}/{x}/{y}.png` | raster tile template for the server-rendered snapshot |
| `CAIRN_MAP_USER_AGENT` | — | identifies your instance to the tile provider; the public OSM tile server requires a meaningful value, see its usage policy |
| `CAIRN_MAP_TIMEOUT` | `15s` | per-tile fetch timeout |
| `VITE_MAP_STYLE_URL` | OpenFreeMap Liberty | **build-time** variable of the web UI, not read by the server: point it at your own MapLibre style JSON when you build the image yourself |

## Request limits

These limits are fixed in the server, not configurable:

| Request | Limit | Over the limit |
| --- | --- | --- |
| Connect-RPC message (web UI, gRPC, gRPC-Web clients) | 4 MiB per message | rejected by Connect (`resource_exhausted`) |
| File upload, `POST /api/activities/upload` | 64 MiB file, plus 1 MiB multipart framing | `400` |
| Attachment, `POST /api/activities/{id}/attachments` | 32 MiB file, plus 1 MiB framing and caption | `400` |
| JSON request bodies of the REST API and MCP requests | 1 MiB | `400` |
| Provider webhook deliveries, `POST /webhooks/{provider}` | 1 MiB | `413` |

A body over the limit is refused, not truncated.

## Outbound requests

Federation fetches and deliveries and notification webhooks go through an
address guard that refuses to connect to anything that is not public unicast:
loopback, private (RFC 1918, `fc00::/7`), link-local and every other IANA
special-purpose range, among them CGNAT `100.64.0.0/10` (including the
`100.100.100.200` cloud metadata endpoint), `0.0.0.0/8`, `192.0.0.0/24`, the
documentation and benchmarking ranges, `240.0.0.0/4`, NAT64 (`64:ff9b::/96`,
`64:ff9b:1::/48`), 6to4 `2002::/16`, Teredo (`2001::/23`) and any IPv6 address
outside `2000::/3`. IPv4-mapped IPv6 addresses are judged as their IPv4
address. The check runs on the resolved address at dial time, so DNS names
that point inward are refused too, and a webhook URL is validated against the
same guard when it is saved. Redirects are capped, and every hop is dialed
through the same guard.

`CAIRN_FEDERATION_ALLOW_PRIVATE_HOSTS=true` turns the guard off for federation
only (and makes WebFinger lookups use plain HTTP); notification webhooks stay
guarded.

## Worker variables

Provider workers are separate processes with their own, smaller set of
`CAIRN_*` variables (NATS connection, enrollment, provider credentials). They
are listed on the [Providers](/self-host/providers) page.
